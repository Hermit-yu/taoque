# Network-VNO-AI 安全文档（SAFETY.md）

本工具对系统参数的修改采取"默认只读 + 事务式 + 可回滚"策略。

## 1. 默认只读

- 所有 `*_detect.sh` / `*_optimizer.sh` / `*_test.sh`（除测速外）/ `adaptive_engine.sh` / `report_engine.sh` / `monitor.sh` **不写入任何内核参数**。
- 只有 `safe_config.sh` 在用户确认后才会真正应用。

## 2. 测速默认允许，但先明示

- `bandwidth_test.sh` 默认直接执行测速（用户明确要求"默认允许测速"）。
- 但执行前**必须先打印预计流量与时长**（如"预计流量 25MB 以内，单轮上限 10 秒"），不静默产生大流量。
- 可用 `--dry-run` 只看估计不下载；可用 `--url` 指定测试文件；可用 `--time` 控制上限。

## 3. 应用前：自动备份

- `safe_config.sh --apply` 第一步调用 `backup_manager.sh`，把以下文件快照到 `backup/backup-<时间戳>/`：
  - `/etc/sysctl.conf`
  - `/etc/sysctl.d/*`
  - 当前 `recommendations.json`
  - 并记录 `manifest.json` 与 `.last_backup` 指针
- 备份**只新增、不删除**已有备份。

## 4. 应用时：差异预览 + 确认

- 应用前打印将要写入的完整 `90-vno-ai.conf` 内容（差异预览）。
- 要求用户显式确认（`y/N`），或设置环境变量 `VNO_YES=1` 跳过交互（用于自动化场景）。
- 配置只写入**独立的** `90-vno-ai.conf`（`/etc/sysctl.d/`），**绝不覆盖**用户原有 sysctl 配置。
- **幂等擦除再写**：每次写入前先彻底删除旧的 `90-vno-ai.conf`（含符号链接），并清理同目录下其他 `*-vno-ai*.conf` 旧版本残留，再写入当前建议。因此重应用时，上一轮不再需要的 key 会被彻底清除，绝不与新配置残留并存（回滚仍基于第 3 节的备份）。

## 5. SSH 会话保护

- 在远程 SSH 会话中应用高风险变更前，会检测 `SSH_CONNECTION` 等环境变量。避免把自己锁在门外：若检测到是 SSH 会话且即将修改可能影响网络可达性的参数，会额外提示谨慎。

## 6. 应用后：验证

- 写完后立即 `verify_applied`：重新读取实际生效值，与建议值比对，输出"已生效/未生效"及原因。

## 7. 回滚

- `safe_config.sh --rollback`：
  - 删除本工具生成的 `90-vno-ai.conf`；
  - 恢复被备份的**原系统** sysctl 配置（跳过恢复自身配置）；
  - 可选执行 `sysctl --system` 重新加载；
  - **绝不删除用户自己的配置**。
- 回滚是安全的、可逆的、默认不破坏环境。

## 8. 高风险操作清单（需单独确认）

| 操作 | 风险 | 保护 |
|---|---|---|
| 修改 tcp_rmem/wmem | 过大抬升内存压力 | 内存预算封顶 + 确认 |
| 切换拥塞控制（BBR） | 受限虚拟化可能不生效 | 能力门控 + 确认 |
| 切换 qdisc | 可能影响现有流量 | 备份 tc 规则 + 确认 |
| 网卡 RSS/RPS/IRQ 调优 | 高级操作，易误配 | 默认不自动修改，需单独确认 |

## 9. 操作边界

- 不修改文件权限、不改动 SSH 服务本身、不删除任何用户配置文件。
- 所有提示均为大白话，无机器文；每一步都告诉你"做了什么、为什么、如何回滚"。
